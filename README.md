# 笔记问答机器人（RAG）

一个小型 RAG（检索增强生成）项目：把 Markdown 资料切块、向量化后存成本地索引，提问时先检索最相关的片段，再让大模型**只根据这些片段**作答，并显示参考来源。资料里没有答案时，会直接回答"资料里没有相关内容"，不会凭空编造。可以用命令行运行，也有 Streamlit 网页界面。

目前内置的知识库是 TinyRAG 教程（见文末"资料来 md 笔记也可以使用。

## 工作流程

建索引（只需运行一次）：

1. **读取**：读入 md 文件，过滤掉对问答没有用的图片行和直播链接行。
2. **拆单元**：按空行分段；代码块整体算一个单元，不从中间拆开。
3. **合并成块**：把相邻的小单元攒到约 500 字符（由 `build_index.py` 里的 `MAX_LEN` 控制），避免出现孤零零的标题。可选段落级重叠（`OVERLAP`，默认 0，即不重叠）。
4. **拆超长块**：超过上限的块在行与行之间拆开，单行本身超长时才按固定长度硬切。
5. **向量化**：用 bge-m3 把每个块变成 1024 维向量。
6. **保存索引**：块原文、向量和模型名一起存进 `index_500.json`。文件名随 `MAX_LEN` 变化；`OVERLAP` 大于 0 时再加后缀，如 `index_250_100.json`。

问答（每次提问）：

1. 把问题向量化（使用索引里记录的同一个模型）。
2. 用余弦相似度与所有块比较，取最相似的 6 个。
3. 把这 6 个块和问题拼成提示词，交给 DeepSeek，要求只根据资料回答。
4. 打印回答；如果回答不是"资料里没有相关内容"，同时打印参考资料及相似度分数。

## 技术栈

- Python 3.9 及以上（开发环境为 3.14）
- 向量化：`BAAI/bge-m3`，通过硅基流动（SiliconFlow）的 OpenAI 兼容接口调用
- 大模型：DeepSeek（`deepseek-flash`），同样通过 `openai` 库调用
- `numpy`：计算余弦相似度
- `python-dotenv`：从 `.env` 读取 API Key网页界面

## 项目结构

```
Retell/
├── data/
│   └── tinyrag_readme.md   # 知识库资料
├── embeddings.py           # 向量化：BaseEmbeddings 基类 + SiliconFlowEmbedding
├── utils.py                # 读取与切块：read_markdown、split_blocks、merge_blocks（支持段落级重叠）、split_long、load_chunks
├── vector_store.py         # 索引：build_index、save_index、load_index，以及 cosine、search 检索
├── llm.py                  # 大模型：chat 调用 DeepSeek，answer 拼提示词并作答
├── rag.py                  # 问答流程：ask（检索 + 作答）
├── build_index.py          # 建索引入口；MAX_LEN 控制块大小，OVERLAP 控制重叠，二者决定索引文件名
├── main.py                 # 命令行问答入口
├── app.py                  # Streamlit 网页界面
├── eval_set.py             # 评测题：EVAL_SET（调参用）和 HELD_OUT_SET（保留集，只用来检验）
├── eval.py                 # 评测：judge 判分、run_eval 按类别统计通过率
├── index_500.json          # 运行 build_index.py 后生成（默认索引）
├── requirements.txt
├── .env                    # API Key（不提交到仓库）
└── README.md
```

## 如何运行

1. 获取代码并进入项目目录：

   ```
   git clone https://github.com/Pippy26/Retell.git
   cd Retell
   ```

2. 创建虚拟环境并安装依赖：

   ```
   python -m venv .venv
   .venv\Scripts\activate        # macOS / Linux 使用：source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. 在项目根目录新建 `.env`，填入自己的 Key：

   ```
   SILICONFLO你的硅基流动Key
   DEEPSEEK_API_KEY=你的DeepSeek Key
   ```

4. 建立索引（会调用向量化接口，只需运行一次；资料或切块方式改变后需要重新运行）。块大小由 `build_index.py` 里的 `MAX_LEN` 控制（默认 500），重叠由 `OVERLAP` 控制（默认 0），索引文件名随之变化，默认是 `index_500.json`：

   ```
   python build_index.py
   ```

5. 开始提问，输入 `exit` 退出：

   ```
   python main.py
   ```

6. （可选）启动网页界面：

   ```
   streamlit run app.py
   ```

7. （可选）运行评测，会按类别打印通过率：

   ```
   python eval.py
   ```

实验时生成的其他索引（如 `index_250.json`）已被 `.gitignore` 忽保留默认的 `index_500.json`。

## 设计要点

- **沿自然结构切块，而不是按固定字数硬切。** 按空行分段，代码块整体保留。一段代码被从中间劈开后，两半单独都读不懂，检索出来也没有用。
- **先拆再合。** 太短的单元合并成块，太长的块再拆开，让块的长度大致落在合适范围内。
- **超长内容有兜底。** 超长块先按行拆；某一行本身超长时再硬切，保限的块。
- **向量化时保留换行。** 换行是代码和列表的结构信息，保留下来，向量更贴近原文。
- **索引里记录模型名。** 不同模型算出的向量不能混用，查询时读取索引里的模型名，保证问题和资料用同一个模型。
- **用提示词约束回答。** 要求只根据资料作答，没有就回答固定的一句话；问到机器人自己、而资料没有明说容时，也要求拒答。程序再根据这句话决定要不要显示参考来源，避免无关的来源误导读者。
- **拒答不用相似度阈值。** 实验 5 显看最高相似度，分不开"沾边但资料没写"的问题和"资料里有答案"的问题，所以拒答只靠提示词，不在检索后加阈值。
- **模块分层，错误向上抛。** `chat` 只负责调用大模型，出错时把异常抛出，由 `main.py` 决定怎么提示用户；网页界面 `app.py` 复用同一套检索和生成逻辑（`rag.py` 的 `ask`）。
- **索引路径只定义一处。** `INDEX_PATH` 由 `MAX_LEN` 和 `OVERLAP` 拼出（`OVERLAP` 为 0 时不加后缀），`main.py`、`app.py`、`eval.py` 都从 `build_index.py` 导入它；建索引的代码放在 `if __name__ == "__main__"` 下面，被导入时不会触发重建。切块参数也只从这里传下去，函数内部不再写死数字。

## 评测与实验

### 评测集

- `EVAL_SET`：13 道题，分四类：资料里有答案（`completely_relevant`，6 题）、答案要跨块凑齐（`cross_chunk`，2 题）、沾边但资料没写、该拒答（`somewhat_relevant`，3 题）、完全无关、该拒答（`completely_irrelevant`，2 题）。
- 判分用关键词：该回答的题检查回答是否包含全部关键词，该拒答的题检查是否包含固定的拒答句，陷阱题检查是否出现不该出现的词。
- `HELD_OUT_SET`：3 道调参时没见过的题，单独放置，只用来检验结论是否通用，不拿来调整参数或提示词。
- 实验规则：一次只改一个值，其他不动；模型每次回答有随机性，所以每组跑 3 次，单次差 1 题视为波动，同一道题 3 次里至少 2 次不通过才算有效下降。除了通过题数，还会看答案块在检索结果里的排名，排名是连续的，比"过/不过"更灵敏。

### 实验 1：取回块数 k（3 对 6）

在 10 道和 13 道题的评测集上（提示词调整之前），`k=3` 共跑 5 次，`k=6` 共跑 4 次。结果稳定不同的只有第 10 题"教程的 Embedding 代码里，默认使用的具体模型名称是什么"：`k=3` 时 5 次全部不通过，`k=6` 时 4 次全部通过。诊断显示答案所在的块排第 6 名，`k=3` 取不到。因此默认 `k=6`。

### 实验 2：块大小

固定条件：`k=6`、提示词不变、13 道评测题，每个块大小跑 3 次。只改 `MAX_LEN`（按字符数，不是 token）。

| 块大小 | 块数 | 3 次总分 |
|---|---|---|
| 250 | 55 | 11/13、11/13、11/13 |
| 500 | 29 | 13/13、13/13、13/13 |
| 1000 | 13 | 13/13、13/13、13/13 |

**结论：** 250 明显更差，每次都固定错同样两道 Embedding 相关的题；500 和 1000 没有差别，默认使用 500。

**250 为什么变差：** 以"默认使用的具体模型名称是什么"一题为例，答案所在的那一块（`get_embedding` 的默认参数）文字没有变，相似度都是 0.554，但 250 时排第 9，500 时排第 5。块切得小，会多出很多和问题字面相似、却不含答案的小代码块，把答案块挤出了 `k=6`。另一道掉分的题（列出 Embedding 模型）没有单独诊断，推测原因类似。

** 已是满分，这套评测集只能发现"变差"，看不出"变好"。
- 资料较短（500 时只有 29 块），1000 时 `k=6` 约取回一半资料，结论不一定适用于更长的资料。
- `k` 固定，块大小变化的同时，送给模型的总字数也在变化，两者没有拆开。
- 500 时答案块排第 5，前 6 名里只剩一格余量。
- 本实验在过滤直播链接（实验 3）之前完成，清理之后只重跑了 250 和 500，没有重跑 1000。

### 实验 3：过滤直播链接

资料开头有一行"手搓RAG直播：[直播链接](https://...)"，对问答没有价值，混在第 0 块里。现在 `read_markdown` 在读取时，除了图片行，还会删掉含"手搓RAG直播"的行。这是按关键词删整行的做法，简单精准，但只针对这份资料，换了资料要调整规则。

验收标准有两条：重建索引后，第 0 块里不再有链接；评测不变差。

**结果：** 第 0 块不再含链接。清理后重跑基线：250 仍是 3 次 11/13，错的还是同样两题；500 是 13/13、13/13、12/13，那次的失败是陷阱题的弱失败（结论正确，但回答里出现了禁用词，见"已知不足"）。清理没有改变评测分数，实验 2 的结论不受影响。

### 实验 4：段落级重叠

**实现：** `merge_blocks` 新增参数 `overlap`（默认 0）。开新块时，从上一块末尾倒着取过来，总长不超过 `overlap`；带过来后如果超过 `MAX_LEN重叠。不会切断代码块和段落。`build_index.py` 里用 `OVERLAP` 控制。

**验证：** `overlap=0` 时，结果和没有这个参数时完全一致；`overlap=100` 时，块数变多，每块都不超过 `MAX_LEN`。

**设置：** 只在 250 已是满分，没有提升空间。`OVERLAP=100`，其他不变。

| 设置 | 块数 | 3 次总分 | "默认模型名称"题的答案块排名 |
|---|---|---|---|
| 250 不重叠 | 约 55 | 11/13、11/13、11/13 | 第 9 名，相似度 0.554 |
| 250 重叠 100 | 57 | 11/13、11/13、11/13 | 第 9 名，相似度 0.555 |

**结论：** 在 250、重叠 100 下，重叠对这份资料几乎没有影响：每次仍过，答案块排名也没有变化。

**为什么没效果：**

- 重叠解决的是"答案恰好被切在两块之间"的问题，而这道题的失败是另一种：答案块是完整的，但被相似的小块挤出了前 6。
- 段落级重叠只带总长不超过 100 字的末尾段落，这份资料里多数段落比这长，所以只有少数块真的带上了重叠，块数只多了约 2 块，干预本身很弱。

**局限：** 没有测 500 加重叠（500 已满分，最多不变）；没有测更大的重叠和字符级重叠；排名只测了一道题。默认不开重叠（`OVERLAP=0`）。

### 实验 5：相似度阈值

**想法：** 检索之后，如果最高相似度低于某个阈值，就不再调用大模型，直接回答"资料里没有相关内容"。这样可以不依赖提示词来拒答。

**做法：** 这一步不改系统，只做统计。用 `index_500.json`，对评测集的每道题取检索结果里最高相似度，按"该回答"和"该拒答"分组，看有没有一个阈值能把两组分开。

**结果：**

| 分组 | 题数 | 最高相似度范围 |
|---|---|---|
| 该回答（资料里有、跨块） | 8 | 0.525 ～ 0.677 |
| 该拒答：沾边但资料没写 | 3 | 0.541 ～ 0.594 |
| 该拒答：完全无关 | 2 | 0.483 ～ 0.500 |

该回答的题里，最低的是"教程 Demo 里切分文本块的默认参数"（0.525）。

**结论：** 阈值只能过滤掉完全无关的题，无法同时做到"拦住沾边但没写的题"拦该回答的题"。完全无关的题和该回答的题之间只有 0.500 到 0.525 的窄缝隙，阈值设在这里，只能拦住无关题；沾边题的最高相似度（0.541 到 0.594）落在该回答题的范围内，会被放行。要拦住沾边阈值得抬到 0.594 以上，该回答的题里最高相似度低于 0.594 的会被一并误拦。

**决定：** 拒答继续靠提示词，不加相似度阈值。完全无关的题在评测中本来就能被提示词拒答，阈值带来的好处很小，却有误拦该

**局限：**

- 样本很小：完全无关的题只有 2 道，沾边题只有 3 道。
- 只用了 `index_500.json` 和 bge-m3，换块大小或向量模型，相似度的分布会变，范围不能直接沿用。
- 只看了"最高相似度"这一个数，没有试过看前几名的分数差、前几名的平均值等其他信号。

## 已知不足与后续计划

已知不足：

- 评测集只有 13 道题，部分类别只有 2 到 3 题，结论的统计力度有限。
- 段落级重叠已实现，但默认关闭，在 250 下没有效果；字符级重叠和测试。
- 直播链接的过滤规则只针对这份资料（按关键词"手搓RAG直播"删整行），换了资料要调整。
- 长度按字符数而不是 token 数计算，是一个简化。
- "有没有答案"靠回答里的固定句子判断，模型换了说法就会失效。
- 拒答完全依赖提示词，没有检索层面的兜底（相似度阈值分不开沾边题，见实验 5）。
- 问到机器人自身配置的问题（例如"这个机器人每次检索取回几个块"）时，提示词管不住：在保留集上示词都没有稳定拒答，模型会把教程示例代码里的值（`k=1`）当成机器人的设置。
- 评测用关键词判分，分不清"提到"和"声称"：回答"资料里没有明确说明……只提到以 InternLM2 为例"，结论正确，也会因为出现了禁用词被判不通过。
- 检索是逐个计算相似度，资料量很小时没有问题，资料多了需要换成向量数据库。
- 目前只支持 md 文件和单轮问答。

后续计划：

1. 做技术文档助手：支持多文件、多轮追问（追问需先改写成完整问题再检索）、回答中给出原文出处。
